> 声明：面经不保证覆盖某一家「原题」，但问题类型和考察点高度重复。医疗、金融类岗位对**合规、审计、可解释**的权重明显高过纯模型效果，下文按这个前提写。

## 背景与岗位画像

我投的大致是两类：一是**医疗信息化 / 医院联合实验室**里做导诊、病历辅读、科内知识库；二是**持牌或强监管金融机构**里做投研辅读、合规问答、运营侧智能助理。公司形态从传统软件厂商到互联网医疗、券商自研、银行金科子都有。初中级（1～3 年相关经验或转岗）常见职名是「大模型应用工程师」「AI 平台开发」「Agent 方向研发」等，面试里**能讲清一条从需求到上线的链路**比会背论文重要得多。

上海本地面试节奏：一面技术 + 二面项目深挖 + 三面交叉（安全/架构/业务）较常见，有的把「安全与合规」单拉一轮。以下面经按**真实被问到的顺序**略作合并，不贴公司名。

## 经历侧写（可照此准备 10 分钟自我介绍）

- **项目主线**：从什么业务痛点出发、你负责哪一段（数据/检索/编排/评测/上线）、最后指标是什么。  
- **失败案例**：POC 没进生产也算，要说清**为什么没上**（效果、成本、流程、政策），比只讲成功分更高。  
- **医疗/金融特供**：是否处理过**脱敏、留痕、人工复核、禁区话题**；有没有和法务/信息科/风控一起定过规则。

## 20 个高频问题（含回答要点）

下面每个问题都按「面试官想听什么」来写，你可以改成自己的故事版本。

### 1. 你们这个 Agent 和「套壳 ChatGPT」本质差别在哪？

**要点**：是否有**可控的工具边界**（只看内部知识库、只调指定 API）、是否有**状态机/流程**（问诊分诊 vs 开放式闲聊）、是否有**评测与回归**（固定用例集 + 线上监控）。医疗/金融里「能聊天」不够，要证明**输出可被约束在业务允许范围内**。

### 2. RAG 架构你会怎么画？检索失败时怎么办？

**要点**：离线入库（解析、切分、向量化）→ 在线检索（混合检索更好交代：BM25 + 向量）→ 重排（可选）→ 提示词组装 → LLM → 后处理（引用片段、拒答）。检索失败：**降级策略**（缩小检索范围、换关键词、转人工节点、返回「未找到依据」而不是胡编）。面试加分项：提一嘴**查询改写（HyDE 等）的成本**，别一上来堆复杂模块。

### 3. 文档切分粒度怎么定？中文医疗文本有什么坑？

**要点**：按结构（章节、段落）优先于固定字数；表格、药品说明书类要**保留字段完整性**。中文没有空格，**语义切分**比纯 `char` 计数靠谱；同一实体跨段时要考虑**重叠窗口**。坑包括：缩写、检验指标单位、阴阳性表述被切开导致检索丢上下文。

### 4. 幻觉怎么控？尤其是「看起来像对的医学/金融结论」

**要点**：三层：**检索 grounding**（回答必须带来源段落编号）、**提示词约束**（不确定就拒绝）、**事后校验**（规则、数值区间、黑名单话术）。医疗场景还会强调**免责声明与人工复核**，不是模型能力强就能省。

### 5. 医疗场景里，你怎么处理患者隐私与脱敏？

**要点**：训练/日志默认**最小必要**；日志里截断身份证、手机号；向量库里是否是原文存储要想清楚。面试常追问：**向量是否可逆推出原文**，必要时哈希或分层权限。不说细节也没关系，但要表现出和信息科/法务对齐过流程。

### 6. 金融业务里，模型输出要不要留审计线索？

**要点**：要。常见做法是：**请求 ID、策略版本、检索命中片段 ID、模型版本、提示词模板版本**一并落库；出错要能复现。Agent 多步时还要记录**每步工具输入输出摘要**（注意脱敏）。

### 7. Agent 编排你用过哪些框架？为什么选它？

**要点**：LangChain / LlamaIndex / LangGraph / 自研状态机都可以，关键是说清**适用边界**：流程固定、分支少 → 状态机足够；多分支、人工介入、长对话 → 图/图编排更合适。**不要为了用框架而用**，初中级岗位反而欣赏你能说出 trade-off。

### 8. ReAct 和 Plan-and-Execute 区别？你们业务更适合哪种？

**要点**：ReAct 是「边想边做」，延迟相对低，适合**工具少、路径短**；Plan-and-Execute 先 plan 再执行，适合**步骤多、可并行**但要防止计划漂移。金融里涉及**资金/交易类工具**往往更倾向强约束流程（甚至不允许模型随意改计划）。

### 9. 工具调用失败、超时、返回脏数据，你怎么设计重试与兜底？

**要点**：**幂等**（同一订单号重复调用不出错）、**超时阶梯重试**、**熔断**（连续失败转人工或降级文案）、**schema 校验**（JSON 解析失败则让模型重试或走模板）。医疗里某些查询接口高峰慢，**异步任务 + 轮询**也要能讲。

### 10. 多 Agent 协作什么时候值得上？有什么明显坏处？

**要点**：拆分的理由通常是**角色边界清晰**（检索员 / 撰写员 / 审查员）或**并行提速**。坏处：**调度复杂、调试困难、成本上升**。初中级项目若只有几千 QPS 文本问答，多数时候**单 Agent + 好流程**更划算。

### 11. 评测怎么做？只有「感觉还行」是不够的

**要点**：离线：**黄金集**（问题、标准要点、允许的来源）；在线：**埋点**（拒答率、用户 thumbs、升级人工率）。医疗/金融还会看**违规样本回放**。你可以主动提：**LLM-as-judge 只能当辅助**，最终要有规则或人工抽检。

### 12. 延迟和成本怎么平衡？

**要点**：缓存（同问题、同检索片段）、小模型做路由/摘要、大模型只做最终生成；流式输出改善体感。**成本面板**：按模型、按租户、按功能拆分账单，方便和业务吵架（这也是工程成熟度）。

### 13. Prompt 注入 / 越狱在企业内网场景怎么防？

**要点**：**输入侧**：过滤、权限隔离；**工具侧**：最小权限 API Key；**输出侧**：敏感动作二次确认。医疗常见攻击面是让模型**绕过禁忌给出诊断**，要靠策略与拦截而不只靠提示词道德绑架。

### 14. 向量数据库选型你怎么聊才不空洞？

**要点**：先说数据量级与查询形态（纯语义 vs 混合过滤）。再谈：**运维成本、权限模型、混合检索支持、灾备**。初中级不必假装用过十种，诚实说 POC 用过哪几种 + 痛点就够。

### 15. Graph RAG / 知识图谱是不是一定要上？

**要点**：不是。结构强、关系推理多（例如药品相互作用、股权穿透）才划算；否则维护图谱的人工很贵。**多数问答先用向量 + 优质 chunks**更务实。你能说出「何时图谱优于纯向量」比背定义高分。

### 16. 线上知识更新频率高时，索引怎么更新？

**要点**：全量重建 vs 增量；**版本号**切换避免半索引状态；更新延迟与一致性（最终一致通常可接受）。金融研报日更场景常见 **T+1 批处理 + 关键实体增量**。

### 17. OCR / 扫描件进知识库，链路怎么设计？

**要点**：扫描 → OCR → 版面分析 → 结构化字段 → 再进入检索。坑在**表格错位**与**手写批注**，面试愿意听你讲**人工抽检比例**与**纠错闭环**。

### 18. 你怎么和风控 / 合规同事对齐「能做什么」？

**要点**：把能力拆成：**自动可做、需人工确认、禁止**。用案例表而不是空话；模型输出旁附**依据与置信度解释**（哪怕是粗粒度）。这点在金融面试里巨加分。

### 19. 如果 POC 指标很好，但没能上线，你怎么复盘？

**要点**：拆原因：**效果以外**（采购、数据权属、责任界定、运维编制）。面试官想听的是你有没有**业务思维**，不是甩锅给领导。

### 20. 未来半年你想补哪块短板？

**要点**：给**可验证目标**，例如：啃完一套 Agent 评测基准并复现报告；或者补**一门合规基础**（个人信息保护法、等保二级三级差异——点到为止即可）。避免「我要学得更深」这种空话。

## 小结

医疗和金融在上海都不算「纯技术说了算」的行业，面试里**把约束条件讲明白**，往往比多报两个模型名更有用。上面 20 个点你可以拆成自己的 checklist：项目介绍各 3 分钟版本、深度追问各准备一则真实细节，现场会顺很多。
